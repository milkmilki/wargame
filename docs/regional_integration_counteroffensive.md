# 区域整合意愿与拔营后攻守转换

## 行为与边界

经营区域的整合收益独立于双边竞争压力。使用已有宗藩根和控制统计，
令 `p=已整合/总陆城`、`q=对方宗藩体系占据的剩余陆城份额`：

```text
integration_bonus = (0.8 + 2.2 * p*p) * (0.5 + 0.5*q)
```

无区域占地冲突、整合完成、同一和平宗藩体系时为零；上限3.0。
27/29且对方占据最后两城时为2.707015。只加入宣战正向收益，
仍受资源、停战、联盟、集结、经营区域和君主资格约束。
军事选州复用既有君主资格：纵横家不能主动征服，但原有法理收复例外保留。
已发动的合法战线不因继位被打断，其他有资格集团成员仍可提出共同目标。

拔营失败在分兵之前协调。旧州战线解除，军队保留战争绑定。
未参战分遣军撤回合法集结点；在途军完成当前路段，不再重开原目标围城。
并行野战全部结束前保留州绑定和战报锁定，不临时补兵或行政扣兵。
已经取得州治的计划继续肃清，不能被旧失败期限挡住。

实际拔营当天登记60天冷却，按 `(war_id, nation_id)` 保存。
同战争集团取成员最晚截止日，期间暂停新建进攻线，但已有第二线和防守继续。
分量拆分保留各自成员期限，合并取最大值；战争ID迁移、退出和灭国沿生命周期清理。
原守方完成围城、来袭与敌占府任务后，同轮释放防守绑定并选州反攻，次日事件规划不被当天吞掉。
没有合法目标或君主禁攻时允许驻守，不使用强制交换整场战争角色的回合状态机。

## 接口与性能

- `RegionalStrategy.integration_war_bonus()`：区域控制索引上的常数时间查询，外交批次缓存。
- `GameState.campaign_offensive_cooldowns`：独立于已释放战线的运行期截止日。
- `record_campaign_offensive_failure()`、`campaign_offensive_cooldown_until()`、`prune_campaign_offensive_cooldowns()`：统一记录、集团查询和生命周期清理。
- 集团报告新增 `offensive_cooldown_until_day`；战争详情解释冷却及剩余天数。
- 原生快照版本15增加稳定排序的冷却数组；地图格式不变。

只复用现有军事批次和占领事件，不增加每日全军扫描、目标搜索或寻路任务。
预先解决拔营失败再分兵，避免向失效营地继续填兵。
