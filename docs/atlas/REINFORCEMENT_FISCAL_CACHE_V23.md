# 月度补员复用财政预测入口 v23

2026-10-11；基于 `298d301`。针对最高耗时日中的补员阶段，不改变补员分配和资源规则。

## 实现

月度补员创建新的粮食预测缓存，原先没有注入财政结果。首次构建预测输入时，`ForecastInputBuilder` 会调用静态 `Simulation.monthly_gold_flows()`，重新计算贸易和财政派生，绕过Simulation已有的结构、产出和守军费用缓存。

现在 `ReinforcementPhase.reinforce_nation()` 接受默认兼容的可选准备回调；只在存在有效补员计划和可用人力、即将做资源预测时调用。Simulation注入当前完整贸易及财政报告，同一月度批次只准备一次。独立调用者不提供回调时保留静态入口，不在缓存中保存Callable。

使用完整财政依赖标记，包含月结后的当前国库、库存和守军变化，不拿之前的财政报告直接代替。保留当天待补给标记、二分补员上限、实际军费、粮食保留、共享粮池竞争、取整和接受补员后的预测增量提交。同步和分帧路径共用同一适配器；没有有效计划时不准备额外财政数据。

## 同状态性能

真实地球种子1、40国，欧亚遮罩20°～55°N、−15°～145°，贸易与君主开启。1192节点、234军队，从同一第180天冻结状态交替运行五对独立进程，推进181～215天；175组每日完整NativeSnapshot一致。

表中为五个进程统计量中位数，P95为35日nearest-rank。日均减少1.5%，峰值减少2.6%，补员阶段减少14.4%；五对峰值均下降，四对日均下降，第五对日均增加。P95增加1.36%，未改善该项。日均改善包含其他阶段的测量波动，不能把全部差值归为一次月度适配器的收益。

这是headless计算，不是GUI帧率。只覆盖一个种子、35天及一个月结边界，不作30年审计或整体性能已完成的声明。月初外交、战役与资源预测仍有较高耗时。

## 验证与来源

专项使用覆盖为空的准备适配器恢复原静态预测路径，对照三个种子的同步与分帧完整状态，以及新适配器财政报告与独立静态入口；覆盖实时国库／守军变化、待补给标记、单批次一次准备、满编军队无额外预测。初始有效复现缺少适配器；最终20项检查通过。初次绿色测试将setup阶段的计数误算入无补员场景，修正测量起点后通过，原日志保留。

工作区16项主回归通过，另一次不存在的测试名 `reinforcement_slice_equivalence` 启动失败，不计作覆盖。补跑实际的 `reinforcement_frame_slice_equivalence`（同一运行路径200天）与 `reinforcement_network_cache_equivalence`（40国／160城／90天）通过。隔离提交目录Godot导入及9项回归通过，综合505检查通过；覆盖贸易财政、资源预测、同步／分帧补员、双方战争胜利、领土、模板及历史。既存君主分封夹具失败保留，不删除或算作通过。

正确入口分别从冻结欧亚状态走实际分帧181～215天，PID15848／21768，35组完整每日状态一致，确认启用4个威胁场worker。继承的累计峰值计数保留原记录，不用于本轮GUI或主线程性能推断。
