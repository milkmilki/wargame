# 按需城市威胁场 v20

2026-10-11；基于 `8e0f1eb`，保持当前欧亚遮罩、贸易及君主功能。

## 改动与边界

旧版为每个观察国初始化全图两个字典，按每个军队来源遍历其全部影响节点，累加敌军威胁和友军支援。实际游戏通过 `threat_at()`／`support_at()` 按城市读取；许多全图节点并未被查询。

现在构建时仍按原顺序聚合军队战力、排序来源、计算道路距离与衰减，但冻结每个来源的战力和影响图。第一次查询城市时才按原来源顺序累加，后续直接复用结果。冻结影响图使用私有字典副本，避免后续军队、道路或调用者缓存修改改变已建成的场。

显式读取 `threat_by_city`／`support_by_city` 时补齐原始全图节点顺序；公开字典仍可修改、替换、删除或清空，后续点查询遵守这些修改。手工创建的 `ThreatField.new()` 保留旧的空字典行为。移除仅用于逐源全图累加的 `O:*` 遍历顺序缓存，保留 `D:*`／`I:*` 距离和影响缓存。

不改变60天时间窗、30天衰减、军队战力、移动端点折扣、道路合法性、外交、补给或战争规则。后台 worker 仍读取共享距离缓存并写各自私有结果；按需求和在使用这些结果时发生，不重新读取实时军队或道路。

## 同状态性能

真实地球种子1、40国，北纬20°～55°、西经15°～东经145°；贸易和君主开启。冻结第180天、1192节点、234军队的运行中状态，交替运行五对独立进程，各推进第181～215天。

| 指标 | 原版 | 按需版 |
|---|---:|---:|
| 整日日均 | 244.243ms | 232.834ms |
| 日耗时P95 | 552.864ms | 546.128ms |
| 最大单日 | 869.678ms | 835.749ms |
| AI日均 | 136.801ms | 125.372ms |
| 威胁场构建日均 | 18.289ms | 6.170ms |

表中为五个进程统计量的中位数，P95采用35日nearest-rank。整日日均减少4.7%，P95减少1.2%，峰值减少3.9%；五对日均及峰值均改善。175组完整每日 NativeSnapshot 逐字节一致，求和转移到查询阶段后的成本已经包含在整日计时中。

这些是headless模拟计算，不能当GUI帧率。月结、资源预测、战役规划及行军接触仍是后续优化重点。本轮没有修改画面，也没有重启30年审计。按需算法对实际稀疏查询有利；大量读取全图时仍要完成全部计算，私有影响图副本也占内存，不能宣称任何输入都更快。

## 验证与复现

专项对照独立保存的旧版实现，覆盖种子1、7、2024，原网格及交通节点、驻扎和移动军队、封路、空军队、逆序查询、部分查询后读取全图、只读共享缓存、后续世界和缓存修改、公开字典修改及手工构造。初始旧版可复现30项失败；最终4990项检查通过。

工作区21项回归通过，覆盖串行／多核AI、分帧运行、资源预测、贸易与君主、补给、州战役、正向胜利与被宣战方反攻灭国、领土、模板和历史。模板及历史另在源文件恢复后复跑通过。冻结欧亚世界的实际分帧入口独立对照第181～215天，两版35个每日完整状态一致，确认使用4个威胁场worker；此对照只用于行为验证，继承的累计耗时计数不能作为本轮主线程性能数据。

只含本轮改动的隔离提交目录完成Godot导入及8项回归，专项4990检查和综合505检查均通过；包括串行／多核AI、资源预测、双方战争胜利、模板及历史。此前君主分封测试的已知夹具失败记录沿用v19，本轮没有删除这些测试，也不将其计作通过。

独立诊断PID32616对照同35天完整状态：同步AI构建平均每天准备8.26个场、160.8份来源影响图副本，共14950个影响条目；平均实际记忆32个节点值，而原版对应全图两个字典包含19685个节点值。该计数不包含构建钩子外的重点城解围场，也不是实际RAM测量，但说明本样本的大部分全图累加并未被读取。
