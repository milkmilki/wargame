# 补给改为攻防属性倍率

## 当前规则

按用户后续修正，取消上一轮“实兵人数乘补给率”的攻城准入规则。`Simulation._siege_assault_manpower()` 汇总存活、未士气溃败的实际人数，不再根据补给比例折算或排除整支缺粮部队，亦不套用城墙正面上限。完全断粮也不改变人数口径。

`Army.combat_attack()` 与 `Army.combat_defense()` 统一乘 `clamp(supply_ratio, 0, 1)`。例如10000人、80%补给，人数仍为10000，派生攻防为其他既有修正后的80%。满粮不变，断粮派生攻防为0。基础属性、编制、士气和行军速度不会因查询而被改写；恢复粮食后属性立即恢复。

真实战斗的前线火力与防御读取上述属性，每支部队分别计算，适用于野战、城下野战和纯攻城。正面容量、实际伤亡与地图对比条继续使用真实人数。缺粮减员、士气侵蚀、粮源权限和库存扣除沿用现有规则。

`ArmyPower.effective()` 去掉额外补给折扣，避免派生攻防已经降低后再扣一次；零攻防不再被原先的品质下限抬成非零战力。它返回AI规划战力，不能用来替代实际人数。

城市虚拟守军继续由 `_attach_city_garrison()` 的城内粮食和 `garrison_supply_ratio` 生成既有城防修正，临时守军的 `Army.supply_ratio` 默认为1，避免把同一城内补给重复乘入。本次没有重设虚拟守军的城防曲线。

删除没有运行期调用的旧 `Combat.effective_siege_strength()` 人数折算辅助。战斗规则版本升为5；日志增加逐军补给率，侧方补给摘要采用前线人数加权比例，仅供记录，不拿平均比例替代逐军解算。回放必须读取补给率，缺失时明确拒绝，不能假设满粮。

## 验证与证据

- `supply_combat_attributes`：57项检查，初版51项在修改前34项失败，另复现4项日志回放失败后修复。最终覆盖倍率边界、军费与君主修正相乘、基础属性不变、AI不重复折扣、真实野战／攻城火力、防御、伤亡与日志回放、缺失补给率拒绝，以及不同补给军队的混合前线。
- `field_manpower_requirements`：87项检查，修改前6项失败。覆盖半粮、满粮、断粮均按实际人数准入；人数不足仍封锁，人数足够仍进入攻城；死亡和士气溃败仍排除。
- 完整回归及默认欧亚365天军事烟测的实际种子、遮罩、PID、源码哈希与结果见[证据索引](evidence/supply_combat_attributes/summary.json)。这是正确性检查，不是30年审计或GUI性能测量。
