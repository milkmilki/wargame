# 财政缓存依赖标记的连续数组 v21

2026-10-11；基于 `bfd5a4d`，仅调整两个财政结算依赖标记的城市记录编码。

## 改动

旧版每次检查财政缓存，为每个城市创建一个小数组，记录城市编号、库存、守军、补给比例及当前战乱状态。全图1192个节点，多次预测入口反复创建并序列化这些临时数组。

现在将整数记录写入预分配的 `PackedInt64Array`，补给比例独立保存为 `PackedFloat64Array`；摘要入口保持原来只包含守军与战乱状态的依赖范围。保留城市顺序、64位整数、浮点精度、宗藩、国家、军队及其他原有依赖。完整字节序列仍用于比较，不改成有碰撞风险的短哈希，也不引入跨日的额外缓存。

两个内部标记更新版本号，使恢复旧开发快照时旧格式自然失效。贸易、财政、君主和军事规则均不变，模板格式不变。没有复用v19未证实收益、已撤回的守军依赖缓存。

## 验证与复现

专项以独立保存的旧版标记生成器作对照，验证变更前后具有相同的失效条件。覆盖种子1、7、2024，32位以外和2^53以上的整数、相邻大整数、细于float32的比例变化、零／无穷／NaN、城市顺序、战乱、君主、宗藩、军队、库存、日期及空世界；另用旧标记版本的Simulation对照实际完整财政和贸易报告及暖缓存。

初始有效复现319项检查、6项失败；最终专项415项通过。工作区18项回归通过，隔离提交目录Godot导入及8项回归通过，综合测试各505项通过。覆盖贸易与财政缓存、资源预测、真实贸易结算、串行／多核AI、主动方胜利与被宣战方反攻灭国、军事模板及历史；未删除或计入此前君主分封夹具的已知失败。

另从同一冻结欧亚状态分别运行两版实际分帧入口181～215天，35组完整每日状态一致，确认启用4个威胁场worker。该检查验证运行路径，不使用继承自冻结状态的累计峰值推断本轮GUI或主线程性能。
