# 贸易预测重复指纹优化 v13

2026-10-11。减少同一次冻结预测中的重复输入遍历；本轮验证有效后单独提交，不推送。

## 改动

`Simulation._forecast_trade_and_gold_flows` 在冷请求时先计算完整贸易结构指纹，随后 `TradeNetwork.build_structure` 又计算一次。两次都会遍历城市产值和道路。守卫在优化前记录到一次冷预测计算2次指纹，暖请求没有新的计算，但仍累计为2次。

贸易构建接口新增末尾可选参数 `prepared_fingerprint`，已有调用保持兼容。它仅接受内部调用者刚刚针对同一冻结状态计算的完整指纹，不是跨日缓存，不改变原指纹字段、编码、依赖判断或商路规则。默认、空参数和空世界仍自行计算。Simulation只在本次调用实际计算了完整指纹时传递；从旧探针命中的指纹不会被当作新指纹传递。

Atlas 的锁、贸易中心发布、路线返回值隔离和财政缓存保持原流程。对照开关 `trade_structure_fingerprint_reuse_disabled=true` 恢复重复计算。新增串行诊断计数；不将诊断值写入贸易结果，不声称工作线程并发计数精确。

## 同状态实测

真实地球种子1、40国，欧亚遮罩北纬20°～55°、西经15°～东经145°，贸易和君主开启。1192节点、234支军队，从同一个第180天冻结状态自主推进第181～215天。两个变体仅切换上述开关；v12局部军事AI唤醒在两边均启用。

五次独立进程串行对照，第2、4次反转顺序。表中为各进程统计量的中位数；P95为35个单日样本的 nearest-rank 值。

| 指标 | 重复计算 | 复用当前指纹 |
|---|---:|---:|
| 全日日均计算 | 251.48ms | 248.97ms |
| 贸易结构准备日均 | 13.15ms | 9.84ms |
| 单日P95 | 570.22ms | 569.65ms |
| 最慢一天 | 824.94ms | 825.50ms |
| 35天完整指纹计算次数 | 42 | 24 |

结构准备阶段约减少25.2%，全日日均中位数约减少1.0%。五次中四次全日平均改善，一次变慢；结构准备阶段五次都改善。P95基本不变，峰值没有稳定改善，不将其称为尖峰优化或已经流畅。

175组完整每日 NativeSnapshot 摘要完全一致，没有本轮新增的决策时机或模拟规则变化。实际PID：34620、3160、20636、36576、15596；完整日耗时、阶段、指纹次数、初始摘要和加载源哈希见 `evidence/trade_fingerprint_v13/`。

这些是一个当前欧亚战争状态的 headless 同步模拟计算时间，不是GUI帧率，也不是长期审计。加载源码包含前期未提交的功能和优化；冻结输入生成源码另记于清单。相邻轮次的绝对耗时不能替代本轮配对对照。

## 回归与夹具修正

`trade_fingerprint_reuse` 覆盖冷/暖预测、重复计算对照、完整财政和路线数据一致、默认及空参数、返回值修改、真实领土事务、贸易关闭、空世界、保留旧探针和同对象重新生成。当前欧亚年度商路必须非空；旧提交的欧亚贸易尚未建立实际路线，因此另外用有真实路线的连接网格验证旧接口，不跳过路线数据与修改隔离检查。网格只用于兼容验证，不作为性能输入。

扩大回归时发现，原来的最后通牒财政缓存守卫要求随机局60天内一定出现提交。旧重复计算路径也复现相同失败，双方60天每日状态一致但提交均为0。现在保留自主运行的完整状态和事件数比较，并额外通过真实备战、物理集结和正式提交事务执行确定性最后通牒，要求两条被测路径都确实提交一次、完整状态一致且不增加冷商路构建。不是修改模拟规则或删除事件覆盖。

最终工作区20项有效回归与独立提交目录7项兼容检查记录于证据目录。包括项目编译、核心综合、贸易结构/预测缓存、年度商路、财政依赖、税额分配、真实后台贸易路径、君主集成、战争集团、战争外交分帧、双方胜利/反攻灭国、模板、历史、虚拟守军经济及宣战/最后通牒预测。原始失败和旧路径复现保留，不用失败前的结果替代修正后验证。
