# 贸易结构指纹连续存储 v25

2026-10-11，基于 `c77795d`。保留经济、路线和军事规则，减少结构指纹构造时的数组分配与序列化负担。

## 问题与实现

新的35天诊断继续显示，军事AI的战役部署之外，贸易/财政预测仍占较大计算量。对照前一轮数据，贸易结构指纹阶段日均约6.5ms，冷指纹原先为每个城市、道路创建一条Variant数组。本轮将城市记录改为14列PackedInt64Array和PackedVector2Array，道路改为7列PackedInt64Array与4列PackedFloat64Array。城市和道路数组顺序保留，国家及Atlas年度商路字段不变。

内部版本改为 `trade_structure_v6_packed_records`，仍比较完整字节，不改为可能碰撞的短哈希。整数不经过浮点转换，道路浮点保持64位。仅替换内部依赖指纹，不新增模板格式或长生命周期缓存。

工作区基线已含节点身份、道路精确长度与控制辖区依赖；隔离提交也补齐这三个字段，避免新记录结构在已提交版本中漏掉对应变化。性能对照的两侧都已有这些依赖，测量收益来自存储方式，而非改变依赖范围。其他未提交年度商路、税收分配和界面功能保持待提交状态。

## 同状态性能

Godot 4.7.1，真实地球种子1，40国、1192节点、1308物理边、234军队，贸易和君主开启，欧亚遮罩20～55°N、−15～145°。从同一第180天状态交替启动五对独立进程，每次推进181～215天。

| 指标（五进程统计量中位数） | 修改前 | 修改后 |
|---|---:|---:|
| 整日日均 | 218.780ms | 216.033ms |
| 日耗时P95 | 327.639ms | 323.681ms |
| 最大单日 | 772.238ms | 764.640ms |
| 结构指纹阶段日均 | 6.481ms | 5.537ms |

日均下降1.26%，P95下降1.21%，峰值下降0.98%；五对日均均下降，四对峰值下降、一对略升。指纹阶段下降14.6%，但整体平均还包含其他阶段的波动，不能把全部2.75ms差值归给这一次修改。

冻结输入的完整指纹从324652字节降至263164字节，减少18.9%；这不代表进程总内存同幅减少。记录改为四个连续数据块，仍有固定表头、国家记录和其他依赖数据。

175组完整每日NativeSnapshot逐字节一致。另从实际分帧入口对照35天，PID35116/35132，启用4个威胁场worker，完整每日状态一致；累计峰值来自冻结输入，不用于主线程性能结论。

以上是headless模拟计算，不是GUI帧率或拖动测试。只有一个种子、35天和一个月结边界；没有长跑或所有布局的性能保证。最高单日仍超过750ms，优化继续进行。
