# 按共享粮池准备资源预测输入 v17

## 卡点与修改

实际PID3104诊断同一第180天状态的后续35天：34次粮食报告中，资源输入构建合计615.79ms，准备好输入后的报告计算67.95ms。四个准备阶段分别约34.11ms（地块预算）、222.36ms（守军）、264.82ms（国家）和70.58ms（粮池），另有构造与调度开销。原代码为一个国家的半年军制审查，重新准备全体国家的守军、产出和累计消耗表。

现在普通预测、军队容量和粮食报告只准备所需国家的完整财政共享粮池。按 `food_pool_holder` 选择所有对应国家，包含多级藩属及无城市的继位财政代理，保持原国家顺序与浮点累加顺序；不会把有共同粮池的军队分开计算。城市和州治仍扫描现有索引，但只汇总本次所需国家，国家与粮池阶段只处理所选成员。

同一评估批次内，其他粮池在首次查询时补齐。已经准备的粮池及其已接受招兵的保守消耗保留；复制外层数组，在新粮池全部准备好后发布，避免分帧期间暴露半成品。现有无范围参数的接口仍完整准备全部国家。日期、世界与现有政治/布局版本失效继续走统一评估缓存检查；没有跨日预测缓存，也没有更改模板格式。

紧急招兵可能绕过容量报告，因此在实际修改军队前补齐其粮池，防止读取空输入。补员仍先查询本国预测再接受分配。守军距离、宜居度、运输、取整、储备目标、财政和AI决策规则均保留。
