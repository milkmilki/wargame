## 保持结果一致的局部优化

- 补给来源只查询道路两端的通行权限，不按粮仓重复查询。
  同损耗排序只为实际候选建立局部镜像排名；候选在排序前收集，避免比较器读取正在重排的数组。
- 每个到达／接触事件扫描军队时同时建立道路分组和岔口候选。
  接触后重新检查当前状态，下一事件重新建立列表；不跨到达、占领或外交事务复用陈旧分组。
  原始全军扫描仍作为独立调用的默认路径。

后续增加日内候选名单：交通节点到达与道路接触只会改变原有道路参与者。
抵达真实治所可能占领、驱离或遣返其他军队，因此下一事件重新扫描全军；
每次让出帧后也重新扫描，以纳入外部下令。名单仍逐事件检查状态，不能把已经交战或驻扎的军队继续当作行军。

## Atlas战略节奏的抽象

- 常规国家战略重评默认15天一轮，每3天合并一批错峰国家。
- 新募军、一般接近预警合并到下一批，最多等待3天；已经排定的紧急唤醒不会被推迟。
- 占领、全局外交变化和战役报告继续提前唤醒。仅处理紧急事件时，不消费常规轮换积压。
- 行军、遭遇、战斗、军粮、士气仍每日运行；月度经济、补员及外交保持原结算边界。
- 旧网格、指定AI策略、非错峰模式和活动中的继位冲突沿用原调度。

15天和3天是可调的游戏抽象，不是经过史料证明的固定军事周期。
这会改变命令发布时间以及后续战争和资源结果，不能继续使用逐日旧哈希作为通过条件。
调度测试覆盖国家轮换、积压合并、局部紧急、全局重评和战役报告；实局对照需另验绑定与库存。

当成整局提速。两组都逐日检查领土、编制、军队、战斗、战线、道路占用和国家库存，同版本三次结果确定。
候选名单版本的90个状态哈希与相同AI调度、未使用候选名单的版本一致。
这些数字是headless纯计算，不含快照、审计、生成和GPU渲染。
