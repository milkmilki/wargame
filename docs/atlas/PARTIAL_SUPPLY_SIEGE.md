# 部分补给攻城准入

> 已被用户后续修正替代：当前只对军队攻防属性乘补给率，攻城准入使用实际人数。见[当前规则](SUPPLY_COMBAT_ATTRIBUTES.md)。以下内容及证据保留为上一轮开发历史。

## 规则

`Simulation._siege_assault_manpower()` 不再因 `Army.starving=true` 排除整支军队。攻城门槛采用所有存活且未士气溃败的攻方军队的 `当前人数 × 当日补给满足率` 之和，最后统一四舍五入为整数人数。补给比例限制在0～1，满编人数不参与这项计数。

例如10000人获得80%当日粮食，贡献8000人；完全断粮贡献0人。各军粮食满足率可以不同，仍分别折算后相加。攻城准入不受城墙正面容量限制。

每次围城结算都以当前折算人数与当前守军的既有R门槛比较：不足时封锁，达到时攻击虚拟守军。补给改善或恶化不会锁定之前的阶段。真实守方野战军仍先按野战规则处理。

这是准入判定的修改。实际扣粮、逐军分配、缺粮损失、士气侵蚀、正面容量及战斗伤亡公式沿用现有规则，没有额外把战斗伤害再乘一次粮食比例。地图对比条继续显示实际人数。

前一轮[交通节点粮源接入修复](TRAFFIC_SUPPLY_FIX.md)保留。本次不改变粮源权限或距离场。旧[围城诊断](SIEGE_SPEED_DIAGNOSIS.md)记录的是修改前的加载版本，其中“部分缺粮整支不计准入”的例子不能作为新规则的预期结果。

## 验证

`field_manpower_requirements` 新增33项检查，总80项。修改前6项行为断言失败，修改后全部通过。

- 80%补给、满粮、断粮、比例上限与下限、死亡和士气溃败。
- 实际人数与编制人数分离，准入不套用城墙正面上限；小数先汇总再取整。
- 通过真实围城入口和战斗结算，4000人对R=3000：50%补给封锁，75%恰好允许攻城，80%允许攻城。
- 同一场围城从50%改善到80%时立即攻城，尽管缺粮标记仍为真；之后断粮退回封锁。
