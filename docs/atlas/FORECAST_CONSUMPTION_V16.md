# AI接受招兵后的耗粮表复用 v16

2026-10-11，基线为 `9a70e71`。本轮仅修改 `DiplomacyAI.commit_force_change`：接受招兵或补员后，为共享粮池每个成员复制原累计耗粮表，再追加已接受增量的逐事件向上取整值。保留原军队的小数粮食债务，不再删除有效表并让后续容量预测反复遍历军队。没有表的输入继续使用原逐军队路径；没有跨日缓存，也不修改真实耗粮、库存、运输或AI选择规则。

提交阶段减少约13.1%，但整日日均和P95没有改善。峰值差约1%，不足以声称主要卡顿已解决。保留此局部改进是因为它消除了已测到的重复工作；不能把它宣传为整日优化成功。以上是headless计算，不是GUI帧率。

证据的原始变体标签沿用开发工具命名：`heap`表示本轮修改前，`levels`表示修改后，不代表本轮改变了行政寻路算法。对应实际源代码及SHA256均保留。
