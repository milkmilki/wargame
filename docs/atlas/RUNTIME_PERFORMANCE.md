# Atlas 地图拖动与日结算修复

后续战争密集期日结算优化与365天状态对照见 [DAILY_COMPUTE.md](DAILY_COMPUTE.md)。
最新补给依赖优化见 [DAILY_COMPUTE_V3.md](DAILY_COMPUTE_V3.md)，其中headless指标不能当作本页GPU帧率。
后续行军优化与仍存在的战役规划阻塞见 [DAILY_COMPUTE_V4.md](DAILY_COMPUTE_V4.md)。

基于 `6a29bb6` 的未提交修改。正式入口仍为 `atlas_military.tscn`。
实际输入是种子1、40国、681州、1115府、2525交通节点，使用降雨v5／宜居度v6。
生成、行政、交通几何和战斗公式不变；修正AI把无所属国的交通节点当成敌方城市的问题。

## 修复

- 底图的纸色、海深、地形罩染和纹理生成后冻结为两张世界坐标图片：
  2048×1024概览及8192×4096细节。拖动只改变地图变换；道路、国界、前线继续使用持久矢量。
  缩放不重新执行底图Shader。细节图用于大于1.35倍的视图；填色和曲线点击规则保留。
- 符号瓦片及其屏幕遮罩按相机、瓦片发布及过渡事件更新，停止操作和空闲帧不重新查询、合成。
  军队绘制命令按位置、战斗、选择、国色及缩放变化失效，不再每帧重建所有圆形和路径。
- 城市／军队局部排序只计算相关节点的键，保留原镜像排序及并列规则。
  AI战略城市集合排除交通节点。视图构建峰值从约53毫秒降到约3毫秒。
- 粮食评估按批次汇总产出、容量、首都距离和驻军参数；同步与分帧共用同一输入构建器。
  输入构建、容量二分和连续征募以约3毫秒为预算让出帧。
  同一国家完整结算后才处理下一国家；同步入口保留。实际征募单步峰值约3.7毫秒，
  消除了单次连续征募约70毫秒的阻塞。
- 信息卡片列表变化时只重建变化的区块，复用其他区块和操作按钮，保留滚动位置。

预绘制底图约136 MiB，纳入缓存计账。总缓存预算从256增至384 MiB；
该场景最终估算约383.2 MiB，六次进程一致，重载后释放原世界资源。
地形符号与文字仍按需补充；军事标记与政治着色保留动态更新，不把易主烘焙进底图。

## 实机测量

Godot4.7.1、RX7600、D3D12 Forward+、1280×720。每次500次真实鼠标事件类型的拖动／缩放调用，
五次独立运行进程；工具栏、国家信息框和外交观察色均开启。
与已有基准一致，关闭VSync以隔离本机隐藏窗口的呈现等待，未改变正式场景VSync设置。
开发缓存仅跳过世界生成，军队、日结算和渲染仍实际执行。基线信息框及工具栏隐藏，
修改后开启，两个配置差异明确保留在日志中。
