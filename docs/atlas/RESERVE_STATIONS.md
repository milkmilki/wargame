# 预备队固定驻地与行军对照

2026-10-11，基线 `c9120584adbf1a592ace4d44d31c2e58f67e8e5d`。
本轮修复国家预备队反复调防，不改变征兵上限、兵力规模、战役目标或补给公式。

## 原因与修改

原 `_balance_national_reserves` 只统计空闲部队。部队前往其他州时，目的地仍被当成空缺；
下一轮可能继续派兵。该函数也没有遵守已有的命令承诺期和90天驻防锁。
因此部队抵达后可能在锁期内被调回，和平发展中也会出现大量往返行军。

现在：

- 在途增援计入目的州，锁定的空闲部队计入当前州，但不参与再次调防。
- 排除战役绑定、动员征用、战前集结、已经安排其他行动、强制撤退和外交遣返的部队。
- 启用既有 `BattleGroup.reserve_target_city`：首次分配后保留驻地，不因为其他州暂时缺兵而轮转。
- 战役释放后的空闲预备队可以返回原驻地；该驻地失守或不可达时重新选址。
- 候选命令用 `reserve_station_city` 携带目标。实际执行成功才保存驻地；排队或执行失败不会发布假驻地。

新招募军队第一次赴任仍会行军；战役、战前集结、撤退和手动命令继续走原有流程。
固定驻地只约束普通预备队均衡调防。地图模板仍是新局模板，不是战役存档。

## 同输入实测

Godot 4.7.1，真实地球种子1、40国、欧亚遮罩北纬20～55°／西经15～东经145°，贸易和君主开启。
基线通过只覆盖旧调防函数的子类运行；其余模拟代码相同，新增候选字段默认未设置。
战争输入使用归档的完整第180天对象图，文件SHA256：
`b9db9e38bd2fbb4f174206917e332982c668ed7f5bf408aaf60bbf0da17089d1`。
推进181～215天，五对独立进程交替运行前后版本；每对恢复相同存档。
采样、审计和序列化不计入日结算时间；计时组没有逐命令观察器。

战争期性能收益较小，不能据此宣称全部卡顿解决；月结和正常战争AI仍是其他耗时来源。

## 验证与复现

- `atlas_reserve_stations`：79项检查覆盖锁、在途计数、固定驻地、失守、断路、回驻地、战前集结、排队失败和其他已计划行动。旧函数复现52项失败，新版全部通过。
- 保留 `atlas_daily_reserves` 的首次部署旧算法对照，以及既有多州防御、动员、补给、战争、反攻灭国和军事持久化回归。
- 本轮20个相关测试进程全部通过，包括核心505项检查、正向征服、反攻灭国、同步／分帧一致性及35天全球军事烟测；全球输入只用于兼容回归，不作为性能基线。
- 另重跑35天战争和180天受控发展，对领土、编组、藩属结构、军队位置、战争／战线／战斗绑定、道路占用和国家库存逐日审计，无错误。
- 手动测量入口：`tests/atlas_reserve_movement_probe.gd`，通过CLI提供 `--simulation`、`--output`、`--days`、`--codec`、`--snapshot`；新局还支持 `--peace=true --payload=...`。
