# Atlas 财政缓存优化 v9

2026-10-11，继续当前工作区日均性能优化；未提交、未推送。

## 实现

围城会每天延长城市的战乱减产截止日期。当前税收只取决于该城市此刻是否仍在减产，旧的Simulation贸易探针却包含未来截止日，导致减产程度未变也重新生成整张商路的精确指纹。现在探针记录当前减产城市集合；减产开始、结束、道路、归属、外交/财政身份、君主、政策和年度中心轮换仍按实际输入更新。

Atlas 物理路径的沿线税额取整也加入精确缓存。缓存键包括总税额、顺序一致的沿线城市及港口/岔路枢纽权重，使用完整64位整数序列，不依靠可能碰撞的短哈希。相同输入复用最大余数分配；实时控制/财政代理仍决定每个城市的受益国家，易主不会继续给旧主发钱。政策、君主导致总额变化，或枢纽权重变化时重算。

每条当前物理路径只保留一份最新分配；年度换点淘汰旧路径时一并清理，道路/布局更新清空对应几何缓存。内部条目不进入公开路线，也不进入地图模板或编年史。返回分配为独立字典，调用者修改结果不会污染内部缓存。旧地图保持原分配流程，生产默认开启；`atlas_tax_allocation_cache_enabled` 仅用于测试对照。

没有修改贸易收益公式、城市产出、战争折扣、领土事务、军事或君主规则。

## 测量输入和限制

默认真实地球种子1、40国，欧亚遮罩20°～55°N、−15°～145°，贸易和君主开启。最新v8代码自主运行180天后冻结，1192节点、234支军队。三次独立进程分别从同一冻结状态对照第181～215天。基线使用旧贸易探针并关闭新取整缓存；其他代码、输入和处理顺序相同。

105组完整每日NativeSnapshot逐字节一致。三次实际PID、加载源SHA256、初始SHA256及完整分阶段耗时见 `evidence/financial_cache_v9/summary.json` 与 `paired-*.json`。

三次进程的均值中位数：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 整体日均计算 | 323.82ms | 316.22ms |
| AI财政准备 | 33.56ms | 26.75ms |
| 其中商路结构指纹 | 9.60ms | 6.51ms |
| 其中商路结构阶段 | 17.59ms | 13.21ms |

整体减少约2.35%，AI财政准备减少约20.3%。月初外交摊销基本未变（11.94→11.89ms）；不把本轮结果说成外交尖峰已解决。父子阶段不可重复相加。

这一阶段的战役、征兵和行军工作量更高，与v8报告的第61～95天状态不同，不能直接比较两个报告的绝对日均数值。全部为headless计算耗时，不是GUI帧率证据。当前主要剩余成本仍在战役规划和行军；本轮只降低财政重复工作，不宣称整体性能问题完成。

## 测试

`atlas_forecast_dependencies` 先复现三次连续延长减产导致的多余失效，再验证探针复用、减产到期、道路更新、君主政策、战争折扣及真实控制权转移；财政报告逐项与独立静态入口比较。

`atlas_trade_allocations` 先复现缺少缓存，再验证初次构建、过路城市易主、减产、枢纽权重、政策、端点产出、返回值修改隔离、道路更新、年度真实换点及64位税额边界。每条路线的分配都与原无缓存最大余数算法直接比较，检查内存条目有界、公开路线无缓存字段以及RNG不变。
