# Atlas 补给缓存优化 v8

日期：2026-10-11。基于当前未提交的年度商路、君主、招兵与交互修改；本轮未提交、未推送。

## 实际问题和修改

正常游戏的后台粮源查询此前绕过驻军长期城市缓存，同城同国军队重复查粮源。现在先读取长期缓存，冷查询按所属国家和所在城市合并；后台只读取冻结世界，查询结束后主线程发布城市缓存。行军仍使用真实道路位置，不把它粗略归入最近城市。围城、断粮、恢复库存和通行变化继续即时更新。

粮仓与藩王首都中继的依赖行在同一个补给批次内只准备一次，不再为每个旅行国重复整理。没有继承争议的 Atlas 世界按可通行国家的实际辖区、粮仓、中继和首都识别变化；无关外国城市易主不再清空本国网络。有继承争议时仍保留全局归属、外交失效依赖，防止漏掉身份及围城特例。

本次真正显著的收益来自修正一个过于保守的分支：原来世界中任意一场继承争议都会禁用 Atlas 的封锁相关性筛选，敌军在自身领土内的移动也触发本国重新寻路。现在无论有没有继承争议，均使用与真实补给寻路相同的 `atlas_edge_access(..., logistics=true)` 识别可进入的道路，包含财政代理身份。筛选只影响缓存失效，实际寻路仍收到完整敌军道路集合；进入己方或代理辖区的真实截粮仍立即生效。旧地图保留全部封锁依赖。

同一冻结批次内，具有相同可通行辖区、粮仓、中继和封锁的国家可以共享粮仓距离场。后台按共享组分工，同组串行交给一个工作线程，避免多个线程写同一个字典；每国仍独立整理粮源顺序与军队位置。共享的是距离，不是军队需求或库存。旧地图、AI的独立预测入口与关闭网络缓存的等价性守卫保持原流程。

未修改耗粮倍率、运输损耗、库存竞争、取整、藩属中继、断粮惩罚和围城时钟。未引入按跳数向外传播的动态最短路算法。

## 同状态实测

真实地球种子1、40国，欧亚遮罩北纬20°～55°、西经15°～东经145°，贸易和君主开启。用优化前的当前版本自主推进到第60天，冻结229支军队、1192个节点的完整运行中状态；当时确有一场继承争议。

三次独立进程，各自从同一冻结状态运行旧补给调度与新调度第61～95天。表中为三次进程结果的中位数：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 全日平均计算 | 117.95ms | 104.01ms |
| 补给平均计算 | 32.48ms | 18.88ms |
| 补给最大单日计算 | 361.79ms | 109.81ms |

全日平均减少约11.8%，补给平均减少约41.9%，补给峰值减少约69.6%。105组完整每日 NativeSnapshot 逐字节相同。实际PID、初始快照SHA256、加载源SHA256、每日分阶段耗时见 `evidence/supply_cache_v8/summary.json` 和三个 `paired-*.json`。

驻军缓存和共享依赖行本身的初轮收益很小；这组世界的移动军队批次查询也没有明显加快。不能把表中收益归功于单纯存储城市跳数或所有查询都变快。仍有行军查询、AI和月初外交等后续瓶颈。

## 正确性与限制

新增守卫覆盖同城重复军队、跨日驻军复用、所属国家隔离、围城开始/解除、粮仓耗尽/恢复、外交、道路关闭和实际行军进度。距离场共享覆盖同权限盟国、宣战后分组及继承争议上下文；依赖测试覆盖无关外国易主、本国走廊失守、首都变化，以及已发动继承战争时第三国在代理辖区的截粮。

18项最终回归通过，包括综合核心505检查、旧补给缓存400天与分帧200天等价、贸易/君主集成、地图模板、主动方胜利、被宣战方反攻灭国、继承战争生命周期和Atlas领土事务。`atlas_supply_runtime` 实际PID24712：两套当前欧亚世界自主运行60天，再对照旧同步与新后台分帧第61～65天；完整状态一致，确实覆盖活跃继承争议。该结果属于headless真实运行路径检查，不作为GUI帧率证据。

代码图谱于2026-10-11刷新。图谱对GDScript仍有未绑定调用，影响范围以实际调用源和回归为依据，不把“0个图关联”当作没有影响的证明。

基线调度保存在 `tests/support/legacy_supply_batch_simulation.gd`，用于独立对照。性能脚本、冻结脚本、对象图编码器及加载源归档以文本保存在证据目录；约103MiB开发冻结文件仍留在 `.dbg/supply-current-day60.bin`，不入库。复现脚本需要先恢复证据中的 `.gd.txt` 为 `.dbg/` 对应 `.gd`，再执行冻结及对照脚本。冻结状态是开发性能证据，不是公开游戏存档格式。

这些是 headless 模拟计算耗时，不是GUI帧率证明；当前样本只覆盖一个战争状态的35天，不构成新版30年审计。共享场保留原算法的浮点近似并列规则；样本的逐字节一致不代表所有浮点输入都已证明一致。
