# Atlas 联盟图复用优化 v11

2026-10-11。目标包含日均计算和单日尖峰；验证有效后单独提交本轮改进。

## 实际瓶颈与改动

上一轮战争集团缓存降低了平均耗时，但第210天仍是约1.2秒的月度尖峰。新诊断发现该日调用 `alliance_bloc` 220次，累计约215ms；仅月初联盟战争整理便调用49次、约71ms。原函数每次查询一个国家，却完整执行一遍所有国家的冲突感知联盟划分。

现在 Atlas 世界的同一外交状态共用完整的并查集结果。保持原字典序合并、敌对成员检查和最终成员顺序；分别缓存包含亡国和仅存续国家两种查询。缓存输入使用完整的国家存亡/继承代理标记、实际外交关系和继承战争双方/战争编号，不依赖短哈希或单一版本号。关系、存亡、继承身份原地变更也会失效；日期、军队、领土、粮食及与联盟无关的王族更新不会失效。

冷构建由互斥锁保护，后台只读查询共享同一份发布结果。发布后的父节点和成员数组保持私有且不修改，调用者拿到独立成员数组。每种查询只留一个当前结果，重新生成清空；旧网格继续原来的逐次计算。原算法提取为 `_build_alliance_components`，`alliance_bloc` 的公开签名和返回约定不变。

本轮未改变外交选择、宣战条件、全局AI唤醒、军队行军、战争处理或经济规则。全局AI集中刷新仍是后续优化项。

## 验证与复现

`atlas_alliance_cache` 在旧代码上先复现两项重复计算，再覆盖暖缓存、返回值修改、盟约变化、矛盾联盟、直接外交变更、存亡过滤、继承争议及代理身份、64组混合关系、同时冷读取、原网格及同对象重新生成。1431项检查通过；查询不消耗模拟随机流。

`atlas_alliance_runtime` 从两份真实欧亚输入自主推进60天，再比较原查询同步路径与新查询真实分帧路径5天。当前工作区贸易和君主开启，最终PID26880，第65天完整状态一致，确有外部战争集团和继承争议。兼容旧配置时按显式君主开关决定是否要求继承争议；当前配置没有跳过该要求。若旧配置第60天仍未形成外部战争，夹具在真实国界上通过正式关系事务建立战争，再实际推进5天，不能以和平局代替战争失效覆盖。
