# Atlas 日结算计算优化

本文保留首轮保持逐日结果一致的实现和量测。后续用户允许战略节奏抽象后的改动、
最终量测及第1029天异常修复，见[后续计算优化](DAILY_COMPUTE_V2.md)；
本页关于AI频率和旧长跑的描述只适用于首轮版本。

2026-10-10，基线为 `cf806910a664be51c686c9c11779ed612ad52632`。
真实地球、种子1、初始40国、4321节点（1796治所、2525交通点）；固定地图输入和现行气候、行政、军事规则。

## 发现与修复

- 预备队均衡驻扎时仍逐军构建最短路场。现在仅在原有调动条件存在成立可能时搜索；
  计数随每次成功命令更新，断联、驻府、动员保留及无所属州的军队仍按原规则判断。
- Atlas 路径缓存每天清空、满32项后整批丢弃。改为32条路径场的LRU，普通路径按世界、
  领土、外交、道路及排序首都失效；避开交战道路的路径仍使用当日键。
- 每个新寻路起点都会对全球约4300个节点排序。Atlas 改为惰性计算原五项镜像排序键，
  堆顺序及等距前驱按相同词典序比较；小图保留原排名方式。
- 同边只有本国军队且没有既有战斗时，不再重复构造遭遇排序几何。
  保留实际敌军接触、增援、第三方阻挡、交通点野战和随机结算顺序。
- Atlas 运行期行军原先仍整段同步执行。现在以完整到达／接触事件为原子单位，
  达到约3毫秒预算后让帧；所有军队仍消耗同一段模拟时间，不给交通节点增加一天。
  同一事件的道路行军时长只计算一次；热循环不再构造临时状态枚举数组。
- 同批补给计划构建期间库存不变，同所有者、同驻地的驻军复用加权损耗。
  行军位置仍精确计算，缓存在取粮与士气恢复前丢弃，避免沿用变化后的粮仓库存。
- 军制结构审计从逐战团扫描全军改为一次索引与计数；保持原有有效／损坏记录判定。
  此项同时用于分封事务和长跑审计，不改变军队编制或容量规则。
- 第三国战线卡位原先逐场野战扫描全军，改为仅对正在野战的道路建立一次军队索引。
  索引限于单次卡位事务；只修改行军进度，保持原有战斗顺序、军队顺序及连续夹取结果。
  没有进行中的野战时不扫描军队，不为其他道路建立临时列表。

没有减少AI决策频率、军队数量、道路或战争参与者；没有更改战斗、供给、外交公式。
显示层和军事几何未修改。

## 测量口径与证据

Godot 4.7.1 Windows，headless 同步 `_advance_day(false)`；逐阶段计时开启。
测量日推进的纯计算墙钟，不含地图生成、渲染、帧等待、快照哈希或审计耗时。
这不是GUI帧率或倍率兑现测试。独立进程运行期间存在其他验证进程，绝对耗时存在系统负载误差；
保留逐日数据、对象数量和完整状态哈希，不能用前期轻载替代战争密集期。

中间版本365天对照：日均 **2602.3 → 1488.8毫秒（减少42.8%）**，
365个完整 `NativeSnapshotBuilder` 哈希逐日相同，包括资源、军队、战斗、外交和随机流。
此版本尚未包含最后的线性军制审计与事件内道路时长复用，不能作为最后版本的唯一证据。
增加卡位索引前的最终365天记录同样逐日匹配原基线，但进程中途调整过CPU亲和性，
其耗时只作原始记录，不与基线据此计算提升比例。
新的固定CPU对照从第240天的完整Simulation对象图恢复，包含AI缓存、计时器及军队引用，
不是仅从地图模板或GameState快照重开模拟；对照连续推进第241～275天。
旧代码为隔离目录中从 `cf80691` 导出的代码，最终代码为当前工作区；逻辑CPU4，亲和性掩码16，
正常优先级、逐进程顺序运行。完整逐日状态SHA256须逐个匹配原365天基线，才能采用耗时结果。
这是一组35天对照，不能代替多次独立进程或实机GUI测量；具体统计见 `summary.json`。

最终顺序对照日均 **7842.3 → 3191.9毫秒，减少59.3%**；中位7613.2 → 3134.9毫秒，
P95为11444.9 → 6010.8毫秒。35天完整状态SHA256均与原365天基线匹配。
AI日均2428.4 → 1025.4毫秒，行军／战斗4813.8 → 1546.6毫秒；补给478.1 → 500.0毫秒，
没有在该样本中测出补给的总阶段改善。绝对耗时明显随进程和系统负载波动，保留所有对照数据。

## 回归与长跑

新增回归：`atlas_daily_reserves`、`atlas_event_slicing`、`atlas_path_order_equivalence`、
`battle_group_index_equivalence`、`atlas_contact_index`；旧算法保留于测试专用oracle，运行时不调用。
路径测试对照完整 `dist/prev`，不只比较长度。事件测试走真实遭遇、围城、军队移除和道路占用事务。
同时复跑主动方获胜、被宣战方反攻灭国、领土事务、模板／历史以及同步／分帧等价性。
2026-10-10随实现增量更新图谱，最终全量索引446文件、4415节点、63415边、438调用流程，未报解析错误。
Godot对象的动态调用可能在图谱中显示为未解析边；`tests_for`的空结果不能替代实际测试日志。
卡位索引的最终11项回归、前一轮15项针对性回归和21项核心回归分别留有证据，不能合并成一次全套运行。

手动30年审计（一年360天，目标10800天）：

```powershell
D:/ProjectICreate/Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/atlas_long_audit.gd -- --audit-years=30
```

运行会重建 `.dbg/atlas-thirty-year/` 的当前证据，重跑前先归档旧目录。
`manifest.json` 记录实际进程、输入、源码SHA256和DebugRunLog；未提交代码不能仅用HEAD标识。
`first-year-profile.jsonl` 记录前365天状态哈希与计算耗时，之后关闭详细profiling。
`status.json` 区分游戏计算与审计耗时；`events.jsonl` 记录月度战线／军队／国家轨迹。
每年保存原生状态快照，硬错误保存失败快照并停止。

旧 `cf80691` 长跑只完成首年360天，尚无硬错误或可疑候选，证据归档于
`.dbg/atlas-thirty-year-cf80691-first-year/`。修复版从第0天重新运行，避免混用代码版本。
前一修复版进程5528最后完整月度记录为第480天，无硬错误或可疑候选；随后进程退出，
没有最终报告或日志退出原因，不能宣称通过。证据独立保存在
`.dbg/atlas-thirty-year-pre-contact-index-interrupted/`，包括原manifest、零字节status及中断说明。
新审计状态写入临时文件后替换，保留完整的上一检查点，避免中断时截断status。
最终版已再次从第0天启动，种子1／40国，实际源码摘要见
`evidence/daily_compute/audit-restart-manifest.json`；交付优化时长跑仍未完成。
30年未完成前不能声明长期战争行为已通过；候选停滞需要结合补给、权限与战役阶段复核，
战争ID退休也可能来自合并，不能直接计作议和。

剩余开销主要是战争密集时的全局到达事件与战役规划，以及月结外交候选。
让帧解决同步阻塞，但不等于降低总计算量；本轮不保证高倍率在大规模战争中达到标称推进速度。
