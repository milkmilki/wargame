# 删除战前主动退避

2026-10-11，基于 `c9e6799` 的工作区。删除 UtilityAI 的两种主动退避：驻城军因敌军优势寻找安全城市，驻边军因敌军优势撤回端点。专用的威胁比、守军折算、安全城市遍历与寻路同步移除；敌军优势不再打破驻城军的命令承诺期。

战败、士气崩溃、断粮导致的溃退、城市失守和外交遣返仍走原模拟流程。断粮突围、战役结束后撤回集结点、州治野战败退回营重整均保留。`ActionCandidate.Kind.RETREAT` 和执行器保留，避免删除这些必要撤离或改变既有枚举编号。

## 前后对照

真实地球种子1、初始40国，城市遮罩为北纬20°～55°／西经15°～东经145°，贸易、君主及动态外交开启。先用修改前AI和当前满编维护规则运行180天，冻结同一模拟状态（231支部队、101支正在行军），再分别推进第181～240天。

每版五个独立进程，交替运行，使用相同记录与计时包装。修改前包装仅覆写单军决策入口，调用归档的旧UtilityAI；修改后调用生产代码。以下耗时为五个进程各自日均值的中位数，排除读档、采样、输出及不变量审计。它们是headless计算耗时，不是GUI帧率。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 60天战前主动退避命令 | 3 | 0 |
| 60天实际进攻／增援／回撤命令 | 331 | 329 |
| 平均正在行军部队 | 152.17 | 150.35 |
| 单军候选选择／日 | 1.053 ms | 0.485 ms |
| 单军决策阶段／日，含命令执行 | 2.716 ms | 2.094 ms |
| 整体AI／日 | 91.844 ms | 91.334 ms |
| 完整日计算 | 172.447 ms | 172.043 ms |

调兵命令减少约0.6%，平均行军数量减少约1.2%。单军候选选择减少约54%，但绝对值只节省约0.57毫秒／日。整体AI和总计算变化不足1%，前后多进程范围重叠，不能判定整体提速。

修改前的主动退避发生在第189天军168、军235及第234天军235；修改后均消除。第184天军120、203、206的“州战场结束，撤回集结点”两版都保留。修改后进攻命令56→58、增援269→268，故总命令不会恰好减少3次。各版五次运行的调兵和行军统计一致。

本窗口整体AI主要计时项为战略快照约34.5毫秒／日、战役规划约30.4毫秒／日。它们远大于普通单军选择；嵌套子项不得相加。这次修改完成了行为简化，没有解决主要卡点。
