# 补给距离场的按需排序键 v22

2026-10-11，基于 `37da4bb`。只修改 `Pathfinding._supply_loss_field()`，旧地图保留全图排名流程。

## 问题与实现

补给网络的冷查询先获取以粮仓为锚点的全图城市排名，再在可通行范围内搜索。默认欧亚有1192个城市与交通节点，但一个国家通常只搜索其中一小部分；新起点、首都和归属变化会产生新的排名表。这部分工作发生在同步补给计划中，运行期则发生在后台距离场准备中。

现在Atlas距离场按访问节点计算原有镜像排序键，堆的等距决胜和前驱决胜直接比较相同的量化键。来源锚点、国家朝向、五个量化分量及浮点近似并列规则不变。额外零损耗起点仍按原顺序入队，重复和无效起点仍按原规则跳过；没有调整运输损耗、权限、封锁、粮仓、中继或分粮。

全图数字排名本来就是这些键的等价类顺序；直接比较键保留相同顺序，包括完全重合的键。使用已有堆比较接口，不更改普通寻路、共享距离场、模板或模拟数据格式。工作区此前的共享补给网络修改仍保留，但未混入本轮提交。

这些是headless模拟计算，不能当GUI帧率。样本包含一天补给冷启动、一个月结边界，仅覆盖一个种子的35天；不证明所有热缓存输入都更快，也不是30年审计。
