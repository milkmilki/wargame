# Atlas 交通节点补给修复

2026-10-11，基线 `a71932a`。此前的定位过程见 [围城诊断](SIEGE_SPEED_DIAGNOSIS.md)。本轮只修复粮源接入，不实施按补给组汇总分粮。

## 问题与改动

Atlas道路按 `Edge.control_city_id` 对应辖区确定通行权，交通节点本身没有国家归属。粮仓距离场已经通过实际道路权限和敌军封锁判断哪些节点可达，但边上军队查询粮源时又按端点的 `City.owner_nation` 检查通行，把 `owner_nation=-1` 的交通节点拒绝了。

`Pathfinding.supply_sources_from_network()` 与非缓存 `_supply_sources_from_edge()` 现在共用端点判断：Atlas交通节点由合法的粮仓距离场决定是否可接入；真实治所、码头及非Atlas地图仍检查原来的国家权限。交通节点不获得虚构的政治归属。

这不把交通节点变成免费粮源：仓库仍必须有库存，后方路线仍须经过有补给通行权的辖区，敌军封锁仍会切断距离场。处于最后一段进攻道路的军队可以从可达的后方路端补给，保持旧版从友方城市端接入战场的语义；距离场不会因此穿过敌方或中立第三国道路。

当日先分粮再行军的顺序、实际库存扣除、逐军分配与攻城准入门槛均未改变；本轮没有修改补员算法。

## 验证

- 新增 `atlas_traffic_supply`，先复现4个真实行为断言失败，再修复。最终18项检查通过，涵盖无归属交通节点、实际仓库距离场、道路内位置损耗、最后进攻路段及抵达后的补给、敌方／中立后方道路、盟友道路、敌军封锁、空仓与真实扣粮。可补给时准确扣3粮；切断后方道路后不再扣不可达库存。
- `atlas_supply_sources` 的416项检查通过。非Atlas数据继续与冻结旧算法逐字节对照；Atlas数据改与独立逐位置图搜索对照，不能继续要求与含有该缺陷的旧端点筛选结果一致。
- `atlas_supply_dependencies`、`atlas_access_and_repatriation`、`atlas_supply_runtime`、`atlas_runtime_equivalence` 通过。默认欧亚同日结算／分帧结算对照跑到65天，包含继承权冲突；全球布局只作为兼容性对照。
- `atlas_territory_transactions` 的126项检查通过，覆盖主动方胜利与被宣战方反攻灭掉宣战方的真实事务。
- 核心 `test_suite`：505通过、0失败；全部脚本编译通过。
- 欧亚真实地球种子1、40国、北纬20～55°／西经15～东经145°、贸易与君主启用，365天军事烟测通过。检查领土、战团、存亡／合法继承军身份、军队位置、战斗绑定、道路占用与库存。该烟测不是全面30年审计，也不是GPU性能测量。

`atlas_masked_military_smoke` 新增可选天数参数，默认仍35天；`run_tests.py --tests atlas_masked_military_smoke --days 365` 可重复本次长烟测。
