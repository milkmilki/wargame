# 调试运行日志

Debug 运行自动记录到 `user://debug_runs/`。Windows 默认目录是 `%APPDATA%/Godot/app_userdata/WorldWar/debug_runs/`，控制台会打印绝对路径和实际种子。文件名包含 UTC 启动时间、进程 PID 和单调计时值；新运行不覆盖旧日志。

每个 `.jsonl` 文件一行一条 JSON：

- `session_start`：实际场景、Godot 版本、Git HEAD 和未提交文件状态、战斗规则及快照版本。Git 不可用时明确标记，不阻止游戏启动。
- `generation_requested`：在生成前落盘的实际种子和生成参数，生成失败也能找到请求。
- `world_start`：实际种子、网格/地形模式、随机启动开关、城市布局种子、国家与城市数量、密度、蒙版和地形源路径、单国覆盖参数、历史间隔和对应初始地图模板。每次重新生成或读入地图递增 `world_index`。
- `checkpoint`：每30个模拟日的天数、实体数量、活动战争编号、争位双方人物和参战军队 ID、精确字符串格式的随机流状态。
- `session_end`：正常退出时的最后进度；强制结束或崩溃可能没有此条，之前的记录仍已逐条刷新到磁盘。
- `road_network_rebuilt`：运行中成功重算路网的日期、种子和请求参数。

同名 `-worldN-map.json` 保存该局生成完成后的地图模板，用于核对或重建修改过的地图。这是地图模板，不是完整的运行中存档，不能恢复当日家谱、战争和军队状态。生成参数用于重新运行原生成路径，读入模板用于地图重建；两者不保证消耗相同的随机序列。日志里的战争编号从0开始，界面“战争419”对应418。

日志只在 Debug 构建启用，不改变游戏规则或随机流。Release 不启用。其他调校操作仍应结合当时的操作说明复现。原先已经启动且没有日志的游戏不会因为磁盘代码更新而补出最初的随机种子。

验证入口：`tests/debug_run_log.gd`，覆盖随机启动、实际参数、即时落盘、完整地图模板、每月去重、同局再生、模板载入、正常退出及独立运行文件。
