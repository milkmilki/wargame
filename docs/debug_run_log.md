# 调试运行日志

Debug 运行自动记录到 `user://debug_runs/`。Windows 默认目录是 `%APPDATA%/Godot/app_userdata/WorldWar/debug_runs/`，控制台会打印绝对路径和实际种子。文件名包含 UTC 启动时间、进程 PID 和单调计时值；新运行不覆盖旧日志。

每个 `.jsonl` 文件一行一条 JSON：

- `session_start`：实际Atlas场景、进程PID、Godot版本、Git HEAD和未提交文件状态、战斗规则及快照版本。Git不可用时明确标记，不阻止游戏启动。
- 生成请求与各阶段进度另存于 `debug_runs/atlas_preview/` 的生成日志；生成失败也能找到实际种子与参数。
- `world_start`：实际种子、来源（原生生成、开发缓存或模板路径）、模型参数与options、国家与节点数量、源代码指纹和对应初始Atlas地图模板。每次重新生成或读入地图递增 `world_index`。
- `checkpoint`：每30个模拟日的天数、实体数量、活动战争编号、争位双方人物和参战军队 ID、精确字符串格式的随机流状态。
- `session_end`：正常退出时的最后进度；强制结束或崩溃可能没有此条，之前的记录仍已逐条刷新到磁盘。

同名 `-worldN-map.json` 保存该局生成完成后的地图模板，用于核对或重建修改过的地图。这是地图模板，不是完整的运行中存档，不能恢复当日家谱、战争和军队状态。生成参数用于重新运行原生成路径，读入模板用于地图重建；两者不保证消耗相同的随机序列。日志里的战争编号从0开始，界面“战争419”对应418。

当前Atlas入口自动记录日志，不改变游戏规则或随机流。其他调校操作仍应结合当时的操作说明复现。原先已经启动且没有日志的游戏不会因为磁盘代码更新而补出最初的随机种子。

验证入口：`tests/atlas_entry_contract.gd`，覆盖正式2D入口、真实地球默认值、实际PID/种子、即时落盘、Atlas地图模板、world_index及随机流不变。旧主场景日志测试已随旧场景移除。
