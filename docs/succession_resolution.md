# 争位战争收口

皇子争位仍以攻下首都州治为成功条件。赢下一场野战不会立即改立太子。
争位方在真实野战中整侧战败时，立即锁定兵变失败；此规则也包括围城外壳内
由真实军队参加的城下野战，并且不依赖双方在战斗数组中的 A/B 顺序。
单军低士气、整场平局，以及仅对虚拟城市守军的攻城失败，不触发此裁决。

结果锁定后，双方参战亲军停止接受新命令。其他已经进行的真实战斗正常打完，
再统一恢复大营、军队与战争绑定，移除临时争位国家，结算失败皇子的死亡及
爵位继承。后续占领或另一场战败不能改写已锁定结果；编年史与政治结算只执行一次。
中央军仍保持中立；普通国家战争的野战失败和兼并规则不变。

连续 180 天没有军事进展时，争位失败。实际行军位置、战斗回合和首都守军
减少属于进展；重新下令、被动恢复士气和守军补充不重置计时。慢速行军及
持续围城可以超过 180 天，只要仍有实际进展。该限制没有另设战争总时长上限。
旧运行状态首次观察时才初始化计时，避免因缺少新字段立即超时。

争位军从大营出发使用原有的专用需求：首都围城需求加可战太子亲军，再乘以
挑战者的需求修正。兵力不足时留营，已经推进的军队继续执行行动。攻营方使用
营内可战争位军及太子的需求修正。界面显示实际争位需求，不把中立中央军或
普通战争分兵下限计入，并明确标注争位战、防守状态与无进展天数。

`SuccessionConflict` 保存上次进展日、参战位置、战斗回合、守军量和结果原因。
Native 快照通过现有字段反射冻结这些新增字段；它们是兼容的追加字段，版本仍为 24。

定向验收：`tests/succession_resolution.gd` 覆盖双方顺序、城下野战、真实平局、
单军低士气、多场战斗及锁定后禁止新命令、超时、慢速真实行军、快照和界面需求。
`succession_counterattack.gd` 验证守方真实出兵取胜；`succession_chain.gd` 保留真实
攻下首都后的成功流程和同步/分片、镜像等价性。

兵变编年史使用结算前的具体封号与姓名，例如「晋王某某兵变」；无爵者记为
「无爵宗室某某」。成功时明确记录废储与改立，在爵位结算后记载废太子新封、
恢复原爵、保留实封或未授爵的实际结果。失败不记作废储，外部干扰收口不记作
太子镇压。事件保存当时封号及废太子处置，后续改爵、登基或改名不重写历史。
`royal_chronicle_names.gd` 覆盖这些记录及历史冻结。
