# 欧亚渡口按河长布置与每河上限

正式欧亚地图源 `assets/terrain/eurasia_hydrology_map_source.json` 使用 `ferry_interval: 0.06`、`ferry_max_per_river: 5`。单位为投影平面上的地图高度，横向距离乘实际地图宽高比；不是公里或经纬度角度。

当前每条相连主河网总计最多5个渡口，规则渡口与必要补建共用额度。人工河段切分、汇合前已归入主河的分支不各自获得新额度；可见支流仍无码头。额度身份按主河网出口确定，不依赖人工河段编号。长河按最长源头到出口的投影弧长自动拉大间距（至少0.06），最多设置五个分散目标，避免直接留下前五个渡口而清空下游。

基准间隔为0.06，受上限限制的长河采用更大间隔，选择所在弧长区间内靠近目标的合法岸点。连续河段共用弧长相位，人工拆分河段不增加渡口。短支路可能只有一个目标区间；支流不设目标。保留两岸不同城市、城市避让、低地及岸路合法性要求，不合适的区间允许空缺。规则渡口仍满足 0.012 的空间净距，同一连续弧长下至少间隔目标间距的 75%，因此实际位置不是机械的等距点。

先检查已有陆路、海运及可航行主河连接。必要时在合法候选中补跨越断开的交通分量的渡口；补建也保留码头净距且不能突破五个上限。随后删除不影响大陆交通的冗余补建，每个保留的补建渡口都须不可单独删除。这是确定性的连通骨架与删除检查，不进行所有渡口组合的全局最优化搜索。上限内无法合法连接时明确返回失败并保留当前世界。

城市选址、省份、河网、道路寻路及可见性简化继续使用原流程；渡口减少后河运按新码头集合生成。新生成地图的元数据 `ferry_spacing` 分别记录 `regular`、`necessary`、`pruned_redundant` 和 `total`，另有主河弧长、候选数、无合法候选区间及耗时。

缺少 `ferry_interval` 的旧地图源保持原规则；有间隔但没有 `ferry_max_per_river` 的地图源仍使用间隔策略而不限制每河数量。模板读入保留保存的码头和路线，移动城市时校验并保留既有码头；不会按新间距重新撒码头。新策略只在重新生成欧亚世界时生效。布局缓存包含间隔、上限与算法版本，水文缓存无需重算。复现日志记录 `maximum_per_river` 和各河 `river_counts`。

## 复现

```powershell
.\.dbg\run_godot_test.ps1 -TestName river_ferry_spacing
.\.dbg\run_godot_test.ps1 -TestName river_ferry_cap
.\.dbg\run_godot_test.ps1 -TestName river_ferry_connectivity
.\.dbg\run_godot_test.ps1 -TestName river_ferry_source
$env:FERRY_TEST_SEED = '12345'
.\.dbg\run_godot_test.ps1 -TestName eurasia_ferry_spacing_world -TimeoutSeconds 180
```

整图测试输出 `.dbg/ferry-spacing-SEED.json`。同种子对照使用此前 `.dbg/road-fix-after-SEED.json`；没有该文件时现场生成旧渡口规则基线。`FERRY_TEST_INTERVAL` 仅用于测试覆盖参数，正式配置仍为 0.06。需要真实渲染预览时设置 `FERRY_VISUAL_DIR`，并以非 headless Godot 运行同一测试。
